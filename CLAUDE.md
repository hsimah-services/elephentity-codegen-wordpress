# elephentity-codegen-wordpress

The WordPress builder for [Elephentity](https://github.com/hsimah-services/elephentity): the
IR in on stdin, the physical schema WordPress needs out on stdout.

Read [README.md](README.md), then `PROTOCOL.md` in elephentity-codegen — that is the
contract this implements, and this file assumes it.

## Working in this repository

There is no local PHP. Everything runs in a container:

```bash
./tools/php composer ci          # style, static analysis, tests
./tools/php composer style:fix
./tools/php vendor/bin/phpunit --filter GoldenTest
```

`composer ci` must pass before committing. PHPStan runs at **level max** and there are
no baseline exclusions — the whole claim is that generated code is provably typed, so
an exception here undermines the product.

## What this builder is

Split out of `elephentity`'s `packages/wordpress`, which now holds only the runtime
half: the adaptor, the manifest loaders, the verifier. Everything here is build-time —
turning a compiled spec into the storage manifest, the post type registration
arguments and the taxonomy registration arguments the runtime adaptor loads at boot.

It also answers `describe` for the `wordpress` driver, including the `Taxonomy`
pattern it ships (`resources/patterns/Taxonomy.yml`) and the handle rules
(`storageRules()` in `bin/eleph-gen-wordpress`) that let a project's spec be validated
against this driver's own limits rather than a hardcoded one.

## Depends on nothing of Elephentity's

| Was | Is now | Why |
|---|---|---|
| `Eleph\Schema\Ir\*` | `src/Ir/*`, a copy | a builder that requires the compiler is not pluggable |
| `Eleph\WordPress\Sql\*`, `Manifest\StorageManifest`, `Taxonomy\TaxonomyPlacement`, `Account\AccountFields` | `src/Sql`, `src/Manifest`, `src/Taxonomy`, `src/Account`, own copies | the physical-schema shapes this builder computes with, and the runtime's own shapes, have to be the same *shape* without being the same *class* |
| `Eleph\Runtime\Storage\RelationKind` | `src/Storage/RelationKind.php`, a copy | the one runtime enum a compiled manifest names as a literal |
| `Eleph\Schema\Wire\BuilderEnvelope` | `src/Protocol/BuilderEnvelope.php`, this side only | two implementations of one format is what makes it a protocol |

**`src/Runtime.php`** is the one place that names the *actual* runtime classes
(`Eleph\WordPress\Sql\TableSchema` and so on) that the exported manifest text refers
to. `StorageManifestExporter` writes `use` lines built from those constants rather than
importing the classes itself, because it cannot: this repository has no dependency on
`elephentity/wordpress` at all. If one of those classes is renamed there, nothing here
fails — the exported file still names the old class, and a project that installed the
new runtime fails to load its manifest at boot. Regenerating `examples/clog` in
`elephentity` is what catches it.

The copies are held in step by the version gate, not a shared classpath.
`BuilderEnvelope::VERSION`/reading `IrCodec::VERSION` is declared here and again in
every other program; when they disagree the build refuses, in both directions.

## Conventions that are load bearing

- **Errors accumulate**, and a driver mismatch is a response with an error, not a
  crash — see `eleph-gen-wordpress`'s handling of a project on a different driver.
- **Naming is derived, never declared**, and it has to agree with the runtime's own
  `QueryCompiler`: `src/Sql/Naming.php` is a second copy of the same rules for exactly
  that reason, not an oversight.
- **The pattern a project `use:`s and the config key `EdgePlanner::isTaxonomy()` reads
  are the same six lines**, shipped from `resources/patterns/Taxonomy.yml` rather than
  hand-copied into every project (elephentity#55).

## Before you commit anything that crosses a repository boundary

**[`.llms/cross-repo.md`](.llms/cross-repo.md) is the closed list of what crosses.** If
you changed something on it, open an issue on each repository it reaches, before or
with the push. [`.llms/README.md`](.llms/README.md) has the rule and
[`.llms/issue-template.md`](.llms/issue-template.md) the shape.

## Before you commit

- `./tools/php composer ci`
- If the generated bytes changed, regenerate `examples/clog` in `elephentity` and read
  the diff — its committed tree is signed, so any change here reaches it
